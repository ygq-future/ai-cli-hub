# `/update` 变更摘要与 Web 通知开关设计

## 目标

- `/update confirm` 只报告实际变化和失败，不把成功检查清单当成结果。
- Web 通知在浏览器权限已授予后仍可由用户随时开启或关闭。

## 更新结果模型

更新器在 pull 前后读取 HEAD。HEAD 变化时查询 commit 列表与 shortstat，组成“代码更新”；没有变化时只说明当前版本已是最新。

配置迁移继续由 `setting-migrate` 执行，但递归合并同时记录新增与删除 key 的点路径，并以内部 JSON marker 交给更新器。数据库迁移在执行前读取目标数据库的 Drizzle migration journal，只摘要实际待应用的迁移；迁移成功后输出内部 JSON marker。SQL 摘要识别表、字段、约束、索引、类型和常见数据操作，无法识别时回退为通用变更说明，不输出原始 SQL。

成功结果分为代码、配置模板、数据库迁移、重启安排。依赖同步、格式检查、类型检查、静态检查、WebUI 暂存构建和产物提升仅在失败时出现。

## 通知状态

浏览器 `Notification.permission` 只表示浏览器授权，`preferences.notificationsEnabled` 表示本站是否实际发送通知。开关关闭时不调用 `new Notification`，但不会也不能撤销浏览器权限。旧偏好没有该字段时，已授权浏览器沿用原行为；浏览器明确拒绝权限时应用开关强制为关闭，并提示从站点权限恢复。

头部铃铛与设置页使用同一持久偏好：已开启显示激活图标，已关闭显示普通图标，浏览器拒绝时显示阻止图标和说明。
